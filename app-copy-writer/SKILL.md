# app-copy-writer

앱의 코드베이스나 설명을 바탕으로 **부제(20자 이내)**와 **상세설명(구체적 UX 흐름)**을 작성하는 스킬.

---

## 언제 트리거되나요?

- "부제 써줘", "상세설명 만들어줘"
- "앱 소개 글 작성해줘", "서비스 설명 써줘"
- "스토어 등록용 글", "앱인토스 제출용 설명"
- 앱이 무엇을 하는지 사용자 입장에서 설명해달라는 요청

---

## 작업 흐름

### 1. 앱 파악

코드베이스가 있으면 다음 파일들을 읽어 전체 사용자 흐름을 파악합니다:

| 읽을 파일 | 파악할 내용 |
|-----------|------------|
| `App.tsx`, 메인 페이지 컴포넌트 | 첫 화면, 핵심 반복 동작 |
| `types.ts` | 도메인 모델 (어떤 데이터를 다루는지) |
| 주요 페이지 컴포넌트 | 기능별 UX 흐름 |

코드베이스가 없으면 사용자에게 핵심 기능 흐름을 질문합니다.

---

### 2. 부제 작성

**기준:**
- **20자 이하** (한글 1자 = 1글자)
- 기능 나열 ❌ → 사용자가 얻는 가치 ✅
- "편리한", "스마트한" 같은 막연한 단어 피하기

**약한 예시 vs 강한 예시:**

| 약한 표현 | 강한 표현 |
|-----------|-----------|
| 할일을 쉽게 관리해요 | 친구와 서로의 할일을 함께 봐요 |
| 편리한 일정 앱 | 우리 둘의 하루를 한눈에 |
| 스마트 메모 서비스 | 떠오른 생각을 바로 팀과 공유 |

---

### 3. 상세설명 작성

사용자가 앱을 처음 열었을 때부터 핵심 기능을 경험하기까지의 흐름을 **구체적으로** 서술합니다.

**작성 규칙:**
- 누구나 이해할 수 있는 쉬운 단어 사용 (개발 용어 ❌)
- 한 문장 = 한 가지 동작 또는 화면 상태
- 실제 버튼 이름, 탭 이름을 **볼드**로 표기
- 원인-결과 구조: "~하면 ~이 나타나요"

**서술 순서:**
1. 첫 실행 시 보이는 화면
2. 핵심 동작 (매일 반복하는 것)
3. 부가 기능 (중요도 순)
4. 소셜/공유 기능
5. 설정 (의미 있는 경우만)

**예시 (할일 공유 앱):**

> 앱을 처음 열면 이번 달 달력이 보여요. 날짜를 탭하면 그날의 할일 목록이 아래에 나타나요. **+** 버튼을 눌러 할일 제목과 시간을 입력하면 해당 날짜에 등록돼요. 할일이 있는 날짜에는 달력에 점이 표시돼요.
>
> 아래 **할일** 탭을 누르면 오늘부터 앞으로의 할일이 날짜 순서대로 한눈에 보여요.
>
> **설정** 탭에서 **초대하기**를 누르면 닉네임을 입력하는 화면이 나와요. 닉네임을 입력하면 나만의 초대 코드가 만들어져요. 이 코드를 친구에게 공유하고, 친구의 코드를 입력하면 서로 연결돼요.
>
> 친구와 연결되면 달력 화면 상단에 친구 이름 탭이 생겨요. 탭을 누르면 친구의 달력과 할일을 볼 수 있어요. 친구의 할일은 읽기만 가능하고, 내 할일만 추가하거나 완료 처리할 수 있어요.

---

### 4. 출력 형식

```
**부제**
[부제 내용] (N자)

**상세설명**
[상세설명 내용]
```
